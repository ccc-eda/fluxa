# Fluxa 模擬器 v0.3 設計：RV64G + MMU

狀態：**設計文件（尚未實作）**。實作時以本文件為藍圖，實作中的取捨記錄到本檔或 `_doc/` 後續筆記。

## 1. 目標與範圍決策

在 v0.2 的 RV32I 核心（`rv32i/`）經驗上，實作一顆 **RV64G + 特權架構 + Sv39 MMU** 的行為級處理器。

| 決策 | 內容 | 理由 |
|---|---|---|
| ISA | RV64G = RV64IMAFD + Zicsr + Zifencei | 「G」的定義即此 |
| MMU | Sv39（含 2MB / 1GB 巨頁）+ 統一 TLB + 硬體頁表走訪 | 特權規格標準；Sv48 留作後續 |
| 特權模式 | M / S / U 三層，含 trap 進出（`mret`/`sret`）、`ecall`/`ebreak` | MMU 必然牽動 S/U |
| Hart 數 | **單 hart** | 多 hart 的 AMO/LR-SC 排程會考驗確定性，屬 v0.4+ |
| C 擴充 | 不做 | 壓縮指令與行為語意無關，只影響取指編碼 |
| PMP / 中斷 | 不做；timer 中斷僅列為選配（以「已退休指令數」驅動，見 §8） | 控制範圍 |
| F/D 實作 | **整數精確 IEEE-754**（見 §6） | 見下方可行性分析 |

非目標：效能、週期精確度（`stage` 層本模擬器不做）、亂序、多核。

## 2. 對 v0.2 rv32i 的延續與差異

延續 rv32i 的骨架與紀律：

- 四級流程 `Fetch → Decode → Execute → Mem`，深度 1 的 FIFO 相連，寫回 FIFO 深度 `WBD`（const 泛型，深度不足 → 死結，如 `err_wb_depth.fx`）。
- Decode 持有暫存器檔與記分板（in-order 停等解決資料相依）；分支/JALR 由 Execute 送回 redirect token（停等，無分支預測）。
- 結束協定：ECALL/EBREAK/非法指令 → 傾印固定長度狀態 token。
- 組譯器即函式：參數型別 = 編碼欄位寬度，超界立即值在組譯時被位寬檢查擋下。

RV64 帶來的差異：

- 資料路徑 u32 → u64；移位量 6 位元；`li` 需 20 位元 → `lui + addiw` 展開（64 位常數用 `lui/addi/slli` 標準序列）。
- **新增 W 型指令**（`addiw`/`slliw`/…：32 位元運算結果符號擴展到 64 位元）— Fluxa 精確整數下寫法為
  `(imm as i32).wrap::<i32>() as i64` 的顯式窄化組合。
- 陷阱傾印長度改為 68（cause/pc/retired/stalls + x0..x31 + f0..f31 低位）。

## 3. 整體架構（tasks 與 channels）

```
                                    satp, SFENCE.VMA
              ┌──────────────────────────────────────────┐
              │                                          ▼
 Fetch ──► Decode ──► Execute ──► Mem ──► WB
   ▲         ▲  │        │  │      │
   │redirect │  │wb      │  │(load)│          Translate（TLB + 頁表走訪）
   │         │  ▼        ▼  ▼      │            ▲ pa/fault   │ walk rd/wr
   └─────────┴──(CSRs 在 Decode；trap 由 Decode 統一發射)     Mem（實體記憶體）
```

| Task | 持有狀態 | 職責 |
|---|---|---|
| `Fetch` | pc、指令映像 | 逐指令送 `Decode`；取指位址先過 `Translate`（U 模式時）；JAL 自算目標，分支/JALR 等 redirect |
| `Decode` | 暫存器檔、記分板、**CSR 檔**、fcsr | 譯碼、資料相依停等、**trap 統一入口**（更新 mepc/mcause/…、跳 mtvec/stvec）、`mret`/`sret`、送 `satp`/`SFENCE.VMA` 給 Translate |
| `Execute` | — | ALU、分支判斷、位址計算、CSR 讀寫（經 Decode 或獨立回路） |
| `Mem` | 資料記憶體、MMIO、保留區（LR/SC） | load/store/AMO、LR/SC、把 walk 讀寫與管線存取送往實體記憶體 |
| `Translate` | TLB（`mem` 陣列 + 線性搜尋） | VA→PA；miss 時走訪頁表（經 `Mem` 的 walk 埠）；回 pa 或頁錯誤；處理 SFENCE.VMA |
| `WB` / 回寫 | — | 依程式順序寫回（沿用 rv32i：Decode 記分板等 wb token） |

單 hart + in-order + 停等的結果：**任一時刻至多一個未完成的記憶體存取或一次走訪**，
這是 Translate／Mem／Bus 之間可以簡化仲裁的關鍵（見 §7 死結紀律）。

## 4. CSR 檔與特權流程

- CSR 檔放 `Decode`（單 hart、in-order，所有 CSR 存取與 trap 都能在此序列化）。
  用 `mem<u64, N>` 以 12 位元位址索引，保留區為非法位址 → 非法指令例外。
- 最小集合：`mstatus`（MIE/MPIE/MPP 等子集）、`mtvec`/`mepc`/`mcause`/`mtval`、
  `misa`、`mhartid`、`mscratch`、`mie`/`mip`（唯讀統計）、`sepc`/`scause`/`stval`/`stvec`/`sscratch`、
  `sstatus`（= mstatus 視窗）、`satp`、`fflags`/`frm`、`mcounteren`/`scounteren`（存取權檢查）。
- Trap 流程：例外偵測點（Fetch：取指頁錯誤；Decode：非法指令/ecall/ebreak/CSR 權限；
  Mem：載存頁錯誤、未對齊、存取錯誤）→ 送 trap token 回 Decode（帶 cause/tval/pc）→
  Decode 排空管線（沿用 rv32i 記分板排空迴圈）→ 依 `medeleg`/`sedeleg` 子集路由到 M 或 S →
  更新 CSR → pc 設為 `tvec`。`mret`/`sret` 在 Decode 還原模式與 pc。
- `SFENCE.VMA`（含 rs2=ASID / rs1=特定位址的過濾語意）與 `satp` 寫入：
  Decode 送命令 token 給 Translate 並**等 ack**——in-order 停等下，此時無在途轉譯，順序可固定。

## 5. Sv39 MMU 細節

- 虛擬位址 39 位元（va[38:12] 為 VPN），三層頁表；PTE 64 位元：`V R W X U G A D` + PPN。
  支援葉 PTE 的 4KB / 2MB / 1GB 巨頁；非葉但 R/W/X 任一為 1 → 保留編碼（非法）。
- 檢查順序依特權規格：V 位 → 權限（U 位 vs 當前模式、SUM/MXR 由 mstatus 控制）→
  A/D 位（本實作**硬體自動設 A/D**，行為模擬中成本極低、可省去軟體 setter 測試）。
- 例外：`load-page-fault(13)`、`store/AMO-page-fault(15)`、`instruction-page-fault(12)`；
  走訪中讀到不可寫的頁表項位置 → `load-access-fault`（簡化，記錄於實作筆記）。
- `Translate` 內的 TLB：`mem<u64, TLB_ENTRIES>` 三路並聯（tag/pte/層級），線性搜尋用 `unroll`。
  **TLB 內容只影響停等次數，不影響任何輸出**——翻譯結果是位址的純函數
  （SFENCE.VMA/satp 命令已把失效時序固定化）。這讓「TLB 大小 1 vs 16 跑出相同結果」
  成為確定性的直接測試（見 §9）。

## 6. F/D：整數精確 IEEE-754

可行性分析（本節結論奠基於已驗證的模擬器能力）：

- 模擬器內建 `Value::Float(f64)` 只支援 `+ - * /` 與比較（`value.rs` 的 `binop`），
  **沒有位元重解讀（bitcast）**，也沒有捨入模式控制；而 F/D 需要
  FMV.X.W/D、以位元形式存進整數記憶體體系、NaN payload、四種捨入模式與 fflags。
  → **不可行**用內建 f64 實作 F/D。
- 反過來，Fluxa 的 120 位元精確整數 + `for`/`unroll` 迴圈非常適合把 IEEE-754
  當成「純整數演算法」實作：解碼（sign/exp/frac）→ 對齊/運算 → 捨入 → 編碼，
  全程 u64 位元模式，記憶體就是普通 u64。

實作計畫（全部 `comb fn`，輸入輸出皆 u64 位元模式）：

| 運算 | 方法 |
|---|---|
| fadd/fsub | 兩運算元展開成 (sign, exp, 53+guard 位有效數) → 對齊 → 120 位整數加減 → 依 `frm` 捨入 → flags（NV/DZ/OF/UF/NX）逐一精確判定 |
| fmul | 53×53 → 106 位精確積（120 位整數放得下）→ 捨入 |
| fdiv | 移位-減法長除法迴圈產生 55+ 位商 → 捨入 |
| fsqrt | 整數牛頓/逐位元法 |
| fcvt 系 | 與 120 位整數互轉，範圍外依捨入模式夾限 → NV/OF |
| fmin/fmax/fclass/fcmp | 對解碼後的 (類別, 位元模式) 比較；NaN 規則依規格 |
| NaN | canonical quiet NaN 產生與 payload 傳播規則按 spec；`fcsr.fflags` 累積在 Decode |
| 非正規數 | 完整支援（flush-to-zero 不做，除非測試需要再列選項） |

驗證策略：以「對照組」測試為主——每個運算的捨入邊界案例（最大/最小正規數、
非正規數、半途捨入、∞、NaN payload）逐一列出手算期望值；
再以「性質測試」補強：`fadd(a,b) 與 (b,a)` 對稱性、單調性抽樣等。

## 7. 確定性與死結紀律

沿用 v0.2 的原則並新增 MMU 相關約束（深度不足要像 `err_wb_depth.fx` 一樣有 err_* 示範）：

- 階段間 FIFO 深度 1；`WBD` 寫回深度需 ≥ 管線可同時在途寫回數（`MAX_INFLIGHT` 上界不變）。
- Translate 的 walk 讀寫通道：單 hart 停等 ⇒ 走訪時管線必然已停在等待翻譯，
  `Mem` 以「管線存取優先、否則服務 walk 埠」的固定順序服務 → 無競態、無需額外深度。
  走訪最多 3 次讀 + A/D 寫回，walk_resp 深度 1 即足夠；err_* 示範驗證破壞此假設時會死結而非亂序。
- 所有「結果與深度無關」的主張都以 §9 的深度掃描測試背書。

## 8. 選配：timer 中斷

KPN 下外部時間源會破壞確定性；若做，timer 以**已退休指令數**觸發
（Decode 計數，達到閾值送一個 token 進 mip.mtip），行為完全可重現。
預設不納入 v0.3 主線。

## 9. 測試計畫

沿用 rv32i 的三層式測試，全部以組譯器函式 + 手算/comptime 期望值撰寫：

1. **煙霧與 ISA 分組**：每個指令組一個 test（ALU/W 型、M、A、F、D、fcvt、CSR、trap 進出）。
2. **系統級**：harness 在資料記憶體映像中預建頁表（測試端以陣列運算產生 PTE），
   M 模式開機 → 建 satp → `mret` 進 S → 再進 U；MMIO 輸出排序陣列、走訪大陣列等實際工作。
   Sv39 測試：4KB/2MB/1GB 映射、權限違例、U 位、SUM/MXR、ASID + SFENCE.VMA 失效、
   未對齊、頁錯誤的 mcause/stval/sepc 檢查。
3. **err_\* 預期失敗示範**：WBD 不足、走訪通道破格、無效 PTE 導致的頁錯誤（改斷言訊息）。
4. **確定性性質測試**：同一程式以不同 const 泛型深度（`Core::<WBD>`、TLB 大小 1 vs 16）執行，
   斷言輸出 token 序列完全相同（規格 §3.10 性質 5 的直接驗證）。

## 10. 里程碑

| 階段 | 內容 | 驗收 |
|---|---|---|
| M1 | ✅ RV64IM 移植（64 位資料路徑、W 型指令、組譯器） | smoke + ALU/M 測試全綠（`rv64.sh`，smoke 1 + tests_basic 20） |
| M2 | Zicsr + M 模式 trap（mtvec/mepc/mcause/mret） | trap 進出與 CSR 權限測試 |
| M3 | S/U + Sv39（Translate/TLB/走訪/SFENCE.VMA/satp） | 系統級頁表測試 + 深度掃描 |
| M4 | A 擴充（LR/SC/AMO，單 hart 語意） | AMO/LR-SC 測試 |
| M5 | F/D 整數精確 IEEE-754 | 捨入邊界對照 + 性質測試 |

### M1 實作筆記（2026-10-29）

- **120 位元上限的兩個繞道**：64 位元左移 `sll64` 分兩次移位、中間 wrap 回 u64；
  64×64 乘積 `mul_hi_lo` 用 32 位元學校乘法分塊（直接 `a * b` 最大近 2^128 會爆）。
  MULH/MULHSU 由無號積修正：`a_s·b_s = a_u·b_u − a_u·2^64·sb − b_u·2^64·sa (mod 2^128)`。
- **`wrap` 是取模不是符號擴展**：`.wrap::<u32>().wrap::<u64>()` 不會 sext；
  W 型指令的正確寫法是 `.wrap::<i32>().wrap::<u64>()`（先變負再擴展）。
- 模擬器 `/` `%` 恰為 trunc-toward-zero、餘數符號隨被除數，與 RISC-V 一致；
  但零除會直接報錯，spec 的除零特殊值（-1 / 被除數）須顯式 `if` 擋在前面。
- RV64 的 SLLI/SRLI/SRAI 移位量為 6 位元，classify 合法性檢查 `inst[31:26]` 而非 7 位元 funct7。
- 64 位元資料記憶體每字 8 位元組：32 位元視角的程式（以 4 位元組步距定址）
  需用 `dimage32()` 把 u32 陣列兩兩打包進 u64 字。

## 11. 開放問題

- Sv39 的 A/D 硬體自動設定：若後續要對齊「軟體管理 A/D」的作業系統行為，需加選項。
- `medeleg` 是否涵蓋全部例外（影響 M2 的路由複雜度）。
- F/D 的 fsqrt 若實作成本過高，可否延到 M5 之後（其餘 F/D 不受影響）。
